# Reservation Web

Веб-интерфейс сервиса бронирования на React и TypeScript. Включает вход и регистрацию, ресурсы, поиск свободного времени, бронирования и удержания, лист ожидания, внутренние уведомления и административные операции.

## Требования

- Node.js 22.12 или новее; рекомендуемая версия — 24.
- npm; версии зависимостей зафиксированы в `package-lock.json`.
- Запущенный backend и PostgreSQL. Подготовка окружения и создание первого администратора описаны в [основном README](../README.md).

## Разработка

Команды выполняются из каталога `frontend`:

```powershell
npm.cmd ci
npm.cmd run dev
```

На Linux/macOS используются аналогичные команды `npm ci` и `npm run dev`. Vite слушает `http://127.0.0.1:5173`, запросы `/api` проксируются к backend на `http://127.0.0.1:8080`. Остановка процесса — `Ctrl+C`.

Для другого адреса backend задайте переменную до запуска Vite:

```powershell
$env:BACKEND_URL='http://127.0.0.1:18080'
npm.cmd run dev
```

`BACKEND_URL` используется сервером разработки, а не браузерным кодом. Учётные данные PostgreSQL передаются только backend.

## Сборка

```powershell
npm.cmd run build
npm.cmd run preview
```

Сборка выполняет проверку TypeScript и создаёт `dist`. Предпросмотр доступен на `http://127.0.0.1:4173`. При публикации статических файлов веб-сервер должен проксировать `/api` к backend; настройки Vite не входят в `dist`.

## Работа приложения

- **Ресурсы:** выбор ресурса, поиск доступности, создание брони, удержания или заявки. Администратор создаёт ресурсы; администратор и назначенный управляющий редактируют ресурс и расписание.
- **Мои бронирования:** история собственных броней, отсчёт времени удержания, подтверждение и отмена.
- **Заявки и уведомления:** предложения листа ожидания, отмена заявки, внутренние уведомления и отметка о прочтении.
- **Пользователи:** раздел администратора для изменения ролей, активности и прав управления выбранным ресурсом.

Пароль регистрации — от 8 до 64 символов с ограничением 72 байта UTF-8. После регистрации выполняется вход; авторизация использует cookie сессии. CSRF-токен запрашивается перед изменяющими операциями. При ответе `401` на защищённый запрос интерфейс возвращается ко входу.

Время брони вводится и отображается в зоне браузера. Рабочие интервалы расписания интерпретируются в зоне ресурса. Дата просмотра расписания и дата начала в форме независимы. Для просмотра созданной записи на другой день выберите соответствующую дату или раздел «Мои бронирования».

Данные автоматически обновляются каждые 15 секунд и после изменений. Доступность является предварительной: конфликт окончательно проверяется backend и PostgreSQL. При потере ответа после изменения интерфейс сообщает о неизвестном результате; перед повтором следует проверить список. Автоматического повторения POST нет.

Управляющий назначается на ресурс, а не получает отдельную глобальную роль. API пока не предоставляет список управляющих: кнопки назначения и отзыва выполняют явные операции. Матрица прав и ручной сценарий проверки находятся в [основном README](../README.md#аутентификация-и-права).

## Проверки

```powershell
npm.cmd test
npm.cmd run build
npm.cmd run test:e2e
```

Vitest выполняет компонентные сценарии с имитацией API. Playwright использует установленный Microsoft Edge. Полный браузерный прогон требует backend с тестовой БД или отдельной схемой и переменных `E2E_ADMIN_USERNAME`, `E2E_ADMIN_PASSWORD` с учётными данными администратора тестового окружения. Сценарии создают пользователей и ресурсы.

Перед запуском необходимо остановить старый Vite, если используется другое значение `BACKEND_URL`. Playwright запускает Vite автоматически либо использует уже работающий процесс на 5173. Без E2E-переменных два сценария реального API пропускаются; проверка перехода на летнее время с имитацией API выполняется отдельно. Результаты и снимки экранов находятся в `test-results`.

## Ограничения

Интерфейс не содержит подключения внешних календарей: соответствующий backend-адаптер ещё не реализован. Перенос брони и календарная сетка также не реализованы. Статус развития сервиса описан в [docs/roadmap-status.md](../docs/roadmap-status.md).
