# Reservation frontend

Минимальный интерфейс на React + TypeScript, HTML и обычном CSS.
Backend: существующий Spring Boot проект в корне репозитория (..), API на порту 8080.
Frontend: http://127.0.0.1:5173. Время отображается в часовом поясе браузера.

## Запуск в Windows

1. Запустите PostgreSQL.
2. В IDEA запустите ReservationApplication из проекта reservation с уже настроенным DB_PASSWORD.
3. Проверьте http://localhost:8080/actuator/health — должен вернуться status UP.
4. Откройте отдельный терминал PowerShell:

~~~powershell
cd C:\Users\Mikey\Desktop\pet\reservation\frontend
npm.cmd run dev
~~~

Откройте http://127.0.0.1:5173. Терминал оставьте открытым. Остановка — Ctrl+C.
Не открывайте index.html двойным щелчком: для API нужен локальный сервер Vite.
Повторная установка зависимостей на этом компьютере не требуется.

После копирования проекта на другой компьютер установите Node.js 24 LTS и выполните npm.cmd ci.
npm.cmd используется вместо npm, чтобы не зависеть от политики исполнения PowerShell.
Пароль PostgreSQL нужен только Java-приложению; во frontend его не вводите.

## Ручная проверка

1. Откройте «Новый ресурс», укажите название и расположение, нажмите «Создать ресурс».
2. Новый ресурс автоматически выбирается. Расписание по умолчанию показывает завтрашний день.
3. Укажите на завтра начало 10:00 и конец 11:00, нажмите «Забронировать».
   Ожидается подтверждённая бронь в списке и исключение занятого часа из свободных интервалов.
4. Повторите запрос с тем же временем: появится сообщение «Это время уже занято».
   Дубликат не должен появиться.
5. Нажмите «Отменить бронь», затем «Да, отменить».
   Статус станет «Отменена», интервал снова освободится.
6. Обновите страницу, выберите ресурс: данные сохраняются в PostgreSQL.
7. Попробуйте конец раньше начала — форма должна показать ошибку.
8. Остановите backend и нажмите «Обновить ресурсы» — появится сообщение об ошибке.
   После запуска backend повторное обновление восстановит список.
9. Уменьшите ширину окна: колонки перестроятся вертикально.

Дата расписания и даты в форме бронирования независимы.
Если создали бронь на другой день, выберите этот день в «Дата расписания».
Начавшиеся брони отменить нельзя. Отменённые записи остаются в истории.
Поиск доступности не резервирует время; конкурентный конфликт окончательно решает PostgreSQL.
При потере ответа после отправки формы результат может быть неизвестен:
проверьте обновлённый список перед повторным нажатием, автоматического повтора POST нет.

## Автоматические проверки

~~~powershell
npm.cmd test
npm.cmd run build
~~~

Первая команда проверяет сценарии компонентов с имитацией API, вторая — TypeScript и сборку.
Браузерные тесты используют установленный Microsoft Edge и требуют работающий backend с БД:

~~~powershell
npm.cmd run test:e2e
~~~

Playwright сам запускает Vite, если порт 5173 свободен.
Реальный браузерный тест создаёт демонстрационный ресурс с префиксом Browser test,
проверяет бронирование и конфликт, затем отменяет бронь. Эти данные остаются в рабочей БД.
При аварийном прерывании проверьте созданную бронь вручную.
Другой браузерный тест проверяет переход на летнее время с имитацией API.
Отдельно скачивать браузер через Playwright для этой конфигурации не нужно.
Снимки desktop.png и mobile.png после тестов находятся в test-results.

## Структура

- src/App.tsx — экран ресурсов, расписание, формы, список и отмена броней.
- src/api.ts — запросы к API, типы, сообщения ошибок и преобразование времени.
- src/styles.css — адаптивный интерфейс без внешних шрифтов и UI-библиотек.
- src/App.test.tsx — компонентные тесты.
- e2e/booking.spec.ts — проверки в браузере.
- vite.config.ts — сервер и прокси /api к http://127.0.0.1:8080.
- package-lock.json — зафиксированные версии зависимостей.

Если backend использует другой порт, измените target в vite.config.ts и перезапустите Vite.
Сборка находится в dist. Для локальной проверки сборки:

~~~powershell
npm.cmd run preview
~~~

Откройте http://127.0.0.1:4173, backend также должен быть запущен.
Для развёртывания dist на отдельном веб-сервере нужно настроить прокси /api;
dev/preview-прокси Vite не включается в статические файлы.

## Границы первой версии

Нет пользователей, авторизации, редактирования ресурсов, переноса броней, календарной сетки.
Есть список ресурсов и бронирований с пагинацией, формы, свободные интервалы и отмена.
Приложение рассчитано на локальную работу. Frontend опубликован в папке frontend общего Git-репозитория;
исходная локальная папка reservation-frontend остаётся отдельной копией и автоматически не синхронизируется.
