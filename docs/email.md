# Уведомления и email

GET/PUT /api/v1/me/notification-preferences: email, emailEnabled, reminderMinutes (1–10080).
Ответ дополнительно содержит providerEnabled: готова ли SMTP-конфигурация. Настройки доступны только текущему пользователю.
Пустой email разрешён при отключённой доставке. Включение требует корректного адреса.

Внутренние уведомления содержат resourceName, startsAt, endsAt, link (/?booking=UUID) помимо прежних полей.
GET /api/v1/admin/email-deliveries возвращает безопасные метаданные доставки без адресов и содержимого писем.
POST /api/v1/admin/email-deliveries/{id}/retry повторно ставит FAILED в очередь.

## SMTP

По умолчанию email выключен, подключения к SMTP нет. Для включения:
EMAIL_ENABLED=true, EMAIL_FROM, FRONTEND_URL,
SMTP_HOST, SMTP_PORT, SMTP_USERNAME, SMTP_PASSWORD. SMTP_AUTH=true и SMTP_STARTTLS=true по умолчанию.
При необходимости TLS: spring.mail.properties.mail.smtp.starttls.enable=true.
Обязательно ограничить время SMTP: spring.mail.properties.mail.smtp.connectiontimeout=5000,
spring.mail.properties.mail.smtp.timeout=5000, spring.mail.properties.mail.smtp.writetimeout=5000.
Хранить пароль во внешнем окружении. Не включать mail.debug.

Email-задания создаются при обработке уже закоммиченного outbox, атомарно с внутренним уведомлением.
Отправка выполняется вне транзакции бронирования и вне транзакции очереди.
При выключенном провайдере задачи сохраняются, обработчик их не захватывает.
Напоминание создаётся один раз для подтверждённой будущей брони в заданном пользователем окне.
Перед отправкой повторно проверяются актуальный адрес, разрешение доставки, активность пользователя;
для напоминаний также проверяются статус и время брони. Отказ от email до этой проверки отменяет отправку
уже поставленных задач. Письмо, уже переданное SMTP, отозвать нельзя.

## Надёжность и ограничения

Захват использует PostgreSQL FOR UPDATE SKIP LOCKED, уникальный ключ дедупликации и аренду 2 минуты.
Каждый захват берёт одну задачу; истёкшую аренду может забрать другой экземпляр.
Результат записывается только владельцем актуального lease_token.
Повтор: максимум 5 попыток, экспоненциальная задержка от 60 секунд до часа.
Последняя истёкшая аренда переводит задачу в FAILED. Администратор может начать новую серию попыток.
Ошибки сохраняются только как SMTP_FAILED/LEASE_EXPIRED, без адресов, паролей или ответа провайдера.

SMTP не предоставляет атомарной записи результата вместе с нашей БД. Сбой после принятия письма
SMTP, но до записи SENT, может привести к повторному письму. Гарантируется дедупликация заданий,
а не exactly-once доставка через SMTP. Таймауты отправки должны быть существенно меньше срока аренды.
